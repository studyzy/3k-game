# 霸王的大陆（3k-game）章程

## Core Principles

### I. Godot 最佳实践

本项目是基于 Godot 3.5.3 的单机游戏工程，所有开发工作 MUST 遵循 Godot 官方最佳实践：

- 场景组织：优先使用场景（`.tscn`）组合节点，避免在代码中手动构建大而复杂的节点树；职责单一的场景才可复用。
- 脚本规范：GDScript 遵循官方 GDScript 风格指南（命名、缩进、类型提示），优先使用信号（signal）解耦节点间通信，禁止硬编码跨层引用。
- 单例管理：全局状态（数据管理、流程调度）MUST 通过 Autoload 单例集中管理，禁止散落的全局变量。
- 资源规范：美术/音频/数据资源放入 `bwdl/resource/` 与 `bwdl/packed/`，禁止在脚本中内联大段二进制数据。
- 版本锁定：工程 MUST 使用 Godot 3.5.3 与 GDScript 1.0 语法，禁止引入 Godot 4.x API 或语法。

理由：工程已有 189 个框架脚本与 1189 个规则脚本的既有结构，遵循统一规范是保持可维护性、避免反编译工程劣化的唯一途径。

### II. 中文注释与中文文档

- 所有新增或修改的代码 MUST 提供中文注释：每个脚本文件头说明该脚本职责，关键逻辑逐段注释；数值公式（伤害计算、开发收益、成功率等）MUST 注明推导依据。
- 所有项目文档（`docs/`、`specs/`、README）MUST 使用中文撰写。
- 面向玩家的文案 MUST 为中文；调试日志可使用中文。

理由：本项目定位为学习研究用途的中文社区工程，中文注释与文档是既定交付标准（README 已声明），也是后续维护者理解反编译代码的前提。

### III. 必要测试纪律（NON-NEGOTIABLE）

- 核心游戏逻辑（数值公式、状态机、数据解析、存档读写）MUST 有单元测试（UT）覆盖后方可合并。
- 测试 MUST 可 headless 运行（`Godot --headless` 或等效方式），不依赖人工操作。
- 修复缺陷时 MUST 先以失败测试复现问题，再修复，最后验证测试通过。
- 测试代码同样适用原则 II（中文注释）。

理由：反编译工程缺乏原始作者保护，无测试的重构极易引入静默回归；"必要"指核心逻辑必测，UI 布局等非逻辑代码不强制。

### IV. 集成测试

以下场景 MUST 有集成测试覆盖：

- 游戏数据加载：`bwdl/packed/data/` 下 JSON（武将/城市/技能/装备/剧本）能被正确解析并注入游戏对象。
- 场景流程：标题 → 内政 → 战争/战斗 → 结算等核心流程串接，依赖反编译脚本之间的契约。
- 存档兼容：游戏存档的写出与读回一致。
- 跨脚本契约变更：修改被多个场景共享的脚本（如 `Flow_Manager.gd`、数据管理类）时，MUST 补充或更新对应集成测试。

理由：本工程的价值在于完整复刻原游戏行为，单元测试无法覆盖脚本间调度与数据契约，集成测试是行为等价性的主要保障。

### V. 简洁性与 YAGNI

- 最小正确 diff：只做被要求的事，禁止无关重构与顺手美化。
- 优先复用工程内既有代码与数据结构，其次 stdlib/Godot 内置能力，最后才新增代码。
- 不为假想的未来需求增加抽象层、配置项或兼容垫片；三行重复优于一个过早抽象。
- 单挑公式、伤害公式等既有实现 MUST 保持行为等价，除有明确证据外禁止"顺手优化"。

理由：本工程是行为复刻项目，任何超出需求范围的改动都会破坏与原版的行为等价性并增加回归面。

## 技术与平台约束

- **引擎版本**：Godot 3.5.3（仓库自带 `Godot_3.6.3.app`/`Godot_3.5.3.app`，以工程 `project.godot` 声明为准），禁止用 Godot 4.x 打开或改写脚本。
- **游戏形态**：单机、离线、无网络依赖；移动端触摸为主（`emulate_touch_from_mouse` 供桌面调试）。
- **数据层**：游戏数据为 `bwdl/packed/data/` 下明文 JSON，可直接修改；禁止重新引入 pck 加密/验签流程。
- **脚本来源**：`bwdl/script/` 为反编译脚本（已加中文注释），`bwdl/packed/sgz_script/` 为原作者明文源码；修改时 MUST 在注释中标注修改点。
- **版权约束**：仅供学习研究，禁止商业用途与二次分发；不得移除 README 中的版权声明。

## 开发工作流与质量门禁

- **校验门禁**：提交前 MUST 通过 `make check`（headless 工程校验）与相关测试。
- **测试门禁**：触及核心逻辑或跨脚本契约的变更，MUST 附带通过的 UT/集成测试（原则 III/IV）。
- **文档门禁**：新增功能 MUST 同步更新中文文档（原则 II）。
- **审查要求**：代码审查 MUST 核对章程合规性：Godot 最佳实践、中文注释、测试覆盖、行为等价。

## Governance

- 本章程是项目开发的最高约束，与其他约定冲突时以本章程为准。
- 章程修订 MUST：说明修订理由、按语义化版本递增（MAJOR：原则删除/不兼容重定义；MINOR：新增原则或实质性扩展；PATCH：措辞澄清）、更新本文件头部日期并重新执行模板同步检查。
- 运行时开发指导见 README.md 与 `docs/`；specify 流程产物（plan/spec/tasks）MUST 通过章程检查门禁。
