# 阶段 0 研究: 修正生成武将头像的八帧表情

日期: 2026-08-28。所有结论均来自对本仓库代码与资产的直接实证，无外部依赖。

## R1: 八帧布局与心情语义

**Decision**: 帧 x = `mood*2*32 + mouthFlag*32`，mood 0~3 = 愤怒/高兴/平静/沮丧，mouthFlag 0=闭 1=张。

**Rationale**: `bwdl/windows/children/actor_face.gd:100` 取帧公式；心情语义由对话用法实证：
- mood=0 → 搜访被拒台词「某虽不才，不事无义之主！」（clSearchCommand.gd:191）
- mood=1 → 搜索/计谋成功（clSearchCommand.gd:118、clPolicyCommand.gd:279）
- mood=2 → 全游戏对话框缺省值（clCity.gd:36、Dialog.gd:20 等）
- mood=3 → 「非常可惜，并无值得一提之事」/失败报告（clSearchCommand.gd:147、clPolicyCommand.gd:310 `4-mood` 反转）
- 播放：闭↔张交替、每两拍 mood+1 循环（actor_face.gd:64）

**Alternatives considered**: 无——这是游戏引擎的既定契约，不可改。

## R2: 原版表情变换规律（像素实证）

**Decision**: 表情差异集中在两个区域，采用「行级几何变换」派生：
- **眉眼区**（行 14~21，峰值 15~18）：怒=眼睛区增高（瞪眼）；喜=眼区压扁 1~2px（眯缝眼）；哀=眼区下移 1px（垂眼）。眉毛不单独移动（与头饰粘连，移动风险大）。
- **嘴区**（行 24~31，峰值 27~30）：闭嘴各心情嘴线保留原样；张嘴=把嘴线中段替换为 2 行高的深色开口。

**Rationale**: 对原版 400 张头像帧差统计（>40 灰度差）：同心情闭vs张差异峰值行 27~30；跨心情闭vs闭差异峰值行 15~18。对刘备（ID 0）四心情眼部放大图目视确认：怒=粗眉压+瞪眼、喜=眯成细缝、平=正常、哀=眉垂+眼下移。

**Alternatives considered**:
- 模板贴换（从原版找标准眉眼贴回）→ 五官位置因脸而异，贴回会错位，弃。
- 移动眉毛增强区分度 → 眉与头饰/发际粘连，自动移动易产生裂缝，弃（眼+嘴差异已足够可区分）。

## R3: 五官自动定位

**Decision**: 从帧 4 检测：
- **眼睛**：行 12~24 内暗色像素（r+g+b<180）计数峰值行为眼中线，上下扩展得眼区。实测 2002/2002 全成功（100%）。
- **嘴**：眼底线 +2 起、行 33 止，找宽 3~12 的暗色横段。实测 1774/2002（88.6%）；漏检 228 张均为胡须遮挡（如 ID 566）。兜底：嘴位 = 眼底线 + 3（实测距离分布众数 +2、中位 +3）。
- 漏检兜底者若嘴位区域大面积深色（胡须），跳过嘴部变形（张嘴帧=闭嘴帧），仅保留眼表情——与原版大胡子武将表现一致。

**Alternatives considered**: 机器学习/模板匹配定位 → 过度设计，几何检测已 100% 命中眼睛，弃。

## R4: 颜色约束策略

**Decision**: 派生只复用帧 4 内已有的颜色（肤色、眼黑、暗色取自原图），不引入新色，无需跑色板映射。

**Rationale**: 帧内已有颜色必然属于该图的色板子集，天然满足 FR-006；比「变换后再 map_to_palette」更快且零色偏。张嘴开口色取嘴区周边最暗色。

**Alternatives considered**: 变换后全图重映射 64 色板 → 多一次全图扫描且理论上可能把原色拉偏，弃。

## R5: 幂等与安全边界

**Decision**: 修复永远从「帧 4」（平静-闭嘴）派生其余 7 帧；帧 4 本身永不修改。跳过 ID ≤ 560（含 546 灰占位）。单张处理：先写 `.tmp` 再原子替换，避免中断留半帧。

**Rationale**: 帧 4 是现有画面的唯一权威来源，以此为基重跑结果恒定（幂等）；「容貌零改变」约束自动满足（FR-003/SC-003）。

**Alternatives considered**: 在已修复的图上增量补帧 → 需要区分「已修复/未修复」状态，复杂化，弃。

## R6: 工具修正点（防复发）

**Decision**: `avatar_composer.to_sheet(frame)` 内部从「复制 8 帧」改为调用 `expressions.derive_sheet(frame)`；`generate_all.py` 与既有调用方无感知。

**Rationale**: 单点修正，所有新生成头像自动合规（FR-009）；复用同一派生逻辑，存量修复与增量生成行为一致。

## R7: 测试策略

**Decision**: stdlib `unittest`，`tools/avatar_gen/tests/`。单元测试用程序合成的 32×40 假头像（画肤色底+黑眼+嘴线）验证：检测定位正确性、四种心情变换的不变量（眼区变化方向、闭/张仅嘴部差异）、幂等（跑两次结果一致）、安全边界（546/原版段跳过）。集成测试：临时目录端到端（复制样张 → fix_all_frames → check_frames 断言合规）。

**Rationale**: 章程原则 III 要求核心逻辑必测且 headless 可跑；unittest 零依赖符合决策阶梯（stdlib 优先）。假头像 fixture 使测试不依赖真实资产（真实资产校验交给 quickstart 步骤）。
