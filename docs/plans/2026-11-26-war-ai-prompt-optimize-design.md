# 战争场景 AI Agent 提示词重构（决策框架化）

日期：2026-11-26
范围：`agent-service/src/agent.ts` 的 `SYSTEM_PROMPT`（战争回合会话）。
不含：白兵战 `battle-agent.ts` 的 `BATTLE_SYSTEM_PROMPT`（另立待办）、任何引擎侧改动。

## 问题

现提示词 3418 汉字、十节「规则字典」，规则齐全但缺战术优先级。模型知道所有规则，
不知道「先算什么、什么该放弃、这局赢在哪」，表现为平权用计、乱移动、把机动力花在低价值目标上。

具体盲区（源码核对）：
- 计策射程上限 6 从未写明，模型不敢推进（`effect_20000.gd:186-188`）。
- 城墙街区免远程、城门格开白兵战的收益没写。
- 没有攻守分化的位置策略；没有「对方在射程外时主动靠拢」的规则。

## 可观测边界（决定规则能否落地）

提示词只能让模型依据**它真能看到的字段**做判断：

- `units[]` 只含武将：pos / ap / soldiers / hp / power / wisdom / skills / main / status …
- `terrain` 只有 `[x, y, 地形名]`，**没有城门耐久**。
- `economy` 只有双方 rice / money + day / max_days + `main_city_pos`（`tools.ts:210-218`）。
- `inspect_terrain(pos)` 只回地形名与是否已列出（`tools.ts:189-207`）。

因此以下量**必须由模型自己从 `units[]` 累计**，规则里要写明算法：

- 我方/敌方总兵力 = Σ `soldiers`
- 敌方开场兵力基线 = 第 1 天记下的敌方 Σ `soldiers`（模型自己记住）
- 白兵总战力 = (士气+战术)×兵力/1000 + 体力×武力×0.04（士气/战术按第三节公式估）

**无法观测的量（城门耐久、城池内政值）不得写进判定条件**，否则模型只能编。

## 目标

每回合先完成局面判定，再按优先级择优，以消灭玩家、赢下战争为最高目标。

## 结构

`SYSTEM_PROMPT` 拆成 5 个常量按序拼接，导出名不变（trace 与测试不受影响），
首段必须仍含「战场指挥官」（`test/trace.test.ts:50/108` 断言）。

| 段 | 职责 | 来源 |
|---|---|---|
| `PROMPT_ROLE` | 身份 + 工具基础约束 | 现有开头段，微调 |
| `PROMPT_STRATEGY` | 模式判定 + 优先级铁律 + 玩家套路 | 全新 |
| `PROMPT_TACTICS` | 位置投资（城门/城墙/射程带）+ 用计射程 | 全新 |
| `PROMPT_RULES` | 原一至十节规则字典 | 原样搬入，仅改冲突条目 |
| `PROMPT_OUTPUT` | 输出约束（reasoning 带模式标记） | 现有，改一条 |

## 一、模式判定（`PROMPT_STRATEGY` 开头）

开场按 **side → 粮草天数 → 兵力对比** 三步判定：

- 剩余天数 = `max_days - day`（攻方超期判负，守方守满判胜）。
- 粮草天数 = `rice / floor(总兵力/250)`，与剩余天数比。
- 三条路线择一：
  - **斩首**（相对判断，不写死武力门槛）：玩家主将在场、我方任一战力最高武将的
    白兵总战力 ≥ 对方主将的 1.5 倍，且按行军表算 1~2 天内能走到可攻击距离。
  - **强攻**：我方总兵力或白兵总战力明显占优，或粮草天数宽裕。
  - **磨盘**：反之；守方且天数富余时默认磨盘。
- 选一条主模式 + 一条备选；主模式前提消失立刻切换。
- **每次工具结果返回后重判**，切换必须写进 `reasoning`。

## 二、优先级铁律（每条附放弃条件）

杀主将 > 断粮 > 占太守府 > 城门/射程带占位 > 白兵换损 > 用计控场 > 消耗 > 移动铺垫。

放弃条件：
- 斩首：摸不到就别行军两天去追，改为消耗。
- 断粮：只对攻方有意义；守方断粮先饿死自己。
- 占太守府：攻方才有即胜收益；守方靠「敌人踩上即败」被动防守即可。
- 占位：只对「有兵且能活到开打」的武将成立，残兵站上去等于送。

**与现有「余力用计铁律」的优先级（冲突处理）**：

原第五节要求「机动力没处花时，哪怕几乎必空也要用计耗掉」。新增规则在此之上加一层：
**若该武将距所有可打法目标都超过射程 6，且移动到射程带（4~6 格）的消耗小于其剩余机动力，
则「靠拢」优先于「空放计策」**——靠拢换来的是后续每天都能打，空放只换一次近乎为零的收益。
靠拢后仍有富余机动力，再按原铁律耗掉。

## 三、位置投资（`PROMPT_TACTICS`）

用一条统一的「站哪一格」判断覆盖三种情形，模型只需判一次位置。

### 用计射程 vs 普通攻击距离（必须分清）

**射程逐计不同，6 只是上限**（`packed/data/skill_system/stratagem.json` 的 `targeting.range`，31 个计）：

| range | 计策 |
|---|---|
| 0 | 十面埋伏、水伏 |
| 1 | 伪击转杀、走石 |
| 2 | 落石、连弩 |
| 6 | 其余大多数（火计/陷阱/虚兵/共杀/落雷/连环/空城计…） |
| 99 / -1 | 要伏 / 霹雳车 |

- 上限公式：6 + 技能距离加成（`effect_20000.gd:186-188`）；度量 `max(|dx|,|dy|)`，斜向也算（`War_AI_astar.gd:126`）。
- 路径必须通：非终点敌军挡路、**城墙挡路**，只有目标本身是城墙时允许「摸到即可」（`War_AI_astar.gd:132-154`）。
- **`units[].skills` 只投影 `{name, ap_cost}`（`StateProjection.gd:89-92`），模型看不到射程。**
  所以提示词不写死「6 格就能放计」，而是要求先 `list_legal_actions(actor)` 确认。
- 计策还有目标地形门槛，推到射程内地形不对仍不合法。
- **普通攻击（attack）**：默认距离 1；`except_blocks` 默认是空数组（`IWar_Attack.gd:23`），
  只有带【城击】的将（`effect_20242.gd:26-33`，站在城格且 AP≥5）才会把城格填进排除集；
  远距离攻击只要是绕路过了城墙就不可选（路径长度 > distance+1，`IWar_Attack.gd:69-76`）。
- 结论：**站在城外几格只能「用计」，打不到人**；想白兵接触必须走到相邻。

### 守方

- 主防线 = **城门格**：1~2 个有兵武将站上去。站在城门格开白兵战时（城门耐久 > 0 才生效，`clBattleFight.gd:519-531`）：
  - 己方多 3 个城门单位（血量=城门耐久、受击免伤 1000、远程打门每次仅 1 点、象兵 15 点）；
  - **代价是强制的**：守方在 `walldoor`/`wallcity` 的步/骑/象被强制转弓（`clBattleFight.gd:930-936`），
    阵型被锁死为 idx 4「守城门」（`clBattleFight.gd:1455-1460`，后排站位 x=6~8），不可自选。
  - 所以城门只放 1~2 个有兵的将，主将与主力输出站平地。
- 次防线 = **城门与太守府之间的平地**：多余武将在此布防。
  **不能写「沿城墙横移」**——城墙格之间不连通（`War_AI_astar.gd:269-278` 只给仙军与带【逾墙】的守方重连），
  且城墙格行军消耗 6/4，横移走不动。
- 城墙格只用于吸火力（免远程：`IWar_Attack.gd:66-76` + `effect_20242.gd:31`、`war_auto_run.gd:1170`），
  站上去自己也失去远程，肉盾/残兵站，弓兵与智者别站。
- 主场 = **太守府**：主将不离场。**不写「远离太守府不超过 6 格」**——小战场宽 16 格，
  该阈值会把次防线判出界，改成方向性约束「主将守府、其余在城门到太守府之间布防」。

### 攻方（条件触发推进，只用可观测状态）

1. 开场**不冲城门**：主动进城门格 = 把城门单位与强制守阵送给对手，且攻方在城格上的撤退免扣未必生效。
   散开站位（防范围计策一次命中多人），先在射程外用计削兵。
2. 高智力武将推进到**距目标 4~6 格**（多数计射程上限）用计消耗；**推进前先 `list_legal_actions` 确认该距离有计可放**。
   这个距离只能放计、不能攻击。
3. **推进触发条件（任一满足）**：敌方当前总兵力 ≤ 第 1 天记录的开场兵力 × 60%；剩余天数 ≤ 5。
4. 破门后守方会冲出来，高武力武将就近白兵斩首，优先打玩家主将。
5. 天数上限一般 30 天，倒排计划。

### 玩家套路（3 条）

- 玩家主将后撤保命 → 定止/咒缚类控住，或改打副将持续消耗；追不上就别追。
- 玩家拖时间 → 攻方按剩余天数倒排，触发条件见 0.5.3（**不重复写「最后 5 天」**，避免两处阈值）。
- 玩家堵城门/堵路 → **城墙街区隔墙打不到**（远程与计策都被排除），只能仙军/逾墙类脱离绕后，
  或改打城内其他目标把他逼出来。**不得写「用远程隔墙消耗」——与引擎行为相反。**

`reasoning` 改为 `【模式:强攻】一句话理由`。Godot 侧 `_show_reason`

## 六、白兵战城门机制（TACTICS 的引用依据）

- 白兵战地形取自**被攻击方**所在大战场格（`clBattleFight.gd:285-296`），为 `walldoor` 且城门耐久 > 0 时
  附加城门单位（`:509-531`）：3 个、(9,4)(9,5)(9,6)、血量 = 城门耐久、受击免伤 1000。
- 城门只挡**横向**攻击（`IUnitLogic.gd:131-133` 纵向射线跳过城门单位）；远程打门每次 1 点、象兵 15 点（`Battle_Unit.gd:577-585`）。
  攻方绕到左侧自动开门（`Battle_Auto_Run.gd:442-447`）。
- **守方在 `walldoor`/`wallcity` 时阵型被强制锁定**：`clBattleFight.gd:1455-1460` 直接
  `return [4]`（守城门）/ `[7]`（守太守府），**不是可选项**。
- **守方在该格步/骑/象被强制转弓**：`clBattleFight.gd:930-936` `_get_special_units_transforms`
  `{步→弓, 骑→弓, 象→弓}`。这才是「守城门全变弓箭手」的引擎来源。
- 弓：射击距离 4、移动规则 0、待机必射、近身 0.5（`attribute_set.json` 小战场·兵种设定·弓）；`射击障碍` 含 `wallcity_88/89`。
- 撤退扣损豁免**只给大战场攻方**（`clBattleFight.gd:374/391/422`，难度≥3）。
