# 剧本初始化出场人物完善方案（2026-08-28）

## 背景

7 个新剧本（liangjin/nanbeichao/suitang/wudai/song/yuanming/qing）的初始出仕分布严重失衡：
qing 清 121 人 vs 大顺 7/大西 5/南明 7/郑氏 5；liangjin 东晋 23 人管 21 城。原版 wolong 为
239 人、每城 3~6、重镇 8~17。另剧本级在野表（citys_unoffice.json）普遍残缺（qing 仅 95 条）
且混有指向已出仕者的失效条目；各快照存在大量「标记在野但大限早于开局」的错状态。

## 机制（依据 Static_Manager.gd:1387-1531 / clCity.gd:739-784 / Actor_Helper.gd:842-918）

- 出仕者：`drama/<剧本>/citys.json` 每城「武将」列表；武将势力 = 所在城「归属」。
- 在野者：剧本级 `citys_unoffice.json` 条目 {城池,登场年,武将}，登场年 ≤ 当前年才可被发现；
  状态必须为「在野」。剧本级文件存在则整表替换顶层（_get_file_path 回退逻辑）。
- 君主必须位于其势力某城的武将列表中，否则 fix_vstate_status 误判灭亡。
- 「出场年」= 首次见诸史书年，即顶层在野表的登场年。

## 确认的决策

1. **口径**：历史归属优先，开局时在世（大限 ≥ 开局年）且史实归属明确即可出仕；
   已出仕者保留（可在同势力内挪城）。密度对齐原版：每城 3~6、都城/重镇 8~15，总量 200~260/剧本
   （池薄则宁缺毋滥）。防穿越闸：出场年 ≤ 开局+20 且开局时已成年者才可出仕。
2. **执行**：7 剧本并行子 Agent，各产出 assign/<剧本>.json（placements+moves+why）。
3. **在野表**：一并重建 = 顶层 2160 条 ∩ 该剧本最终在野者（剧本专属 ID 段排除）。

## 流程

1. `tools/scenario_roster/precompute.py` → context/<剧本>.json（候选池含 md 身份/出场/城市提示、
   42 城含地域/行政区、势力布局、现有部署、剧本专属 ID 段）。
2. 7 个并行子 Agent 按史实产出 assign/<剧本>.json。
3. `tools/scenario_roster/apply.py`：校验（ID 在池、城=势力归属、无重复、君主在城、
   单城 ≤ 17）、写 citys.json 武将列表、快照状态改出仕、大限<开局者改死亡、
   重建剧本级在野表。
4. 终检：JSON 完整性、ID==下标、状态一致性、一人一城、每城/每势力统计报告。

## 不动的东西

- vstates.json（势力/君主/目标城池）、城市归属（归属 -1 空城保持无武将）、
  城市其余属性、actor_skills.json、主表 actors.json（只改剧本快照）。
